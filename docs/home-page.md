## `src/home.js`

### Mobile menu

`#menuToggle` opens `#navPanel`. The button's `aria-label` says what the next
click does («Abre el menú» / «Cierra el menú»). Tapping a link or anywhere
outside closes it; Escape closes it and returns focus to the button. The
wizard and the matizado page copy this behaviour.

### The hero colour preview

The hero shows a photo of a beige SUV and a row of swatches (Original, Rojo
Fuego, Azul Océano, Verde Bosque and more). Choosing one repaints only the
bodywork, keeping reflections and shadows.

How it works, in the markup and CSS:

```
#heroVehicle
  <img class="hero__vehicle-img">       the photo (imgs/assets/suv.webp)
  <span class="hero__vehicle-paint">    the same photo again, with a CSS filter
  <span class="hero__vehicle-tint">     a flat colour, mix-blend-mode: color
```

- Both overlay layers are clipped by the same **mask**,
  `imgs/assets/suv-paint-mask.webp`, whose alpha is 1 on painted bodywork and 0
  on glass, tyres, wheels, chrome, lights, plate and badge.
- `.hero__vehicle-paint` applies `filter: var(--vehicle-filter)`, typically a
  `brightness()` to darken the beige first. With the filter at `none` it draws
  exactly the pixels below it, so the "Original" state is unchanged.
- `.hero__vehicle-tint` fills `var(--vehicle-tint)` in `color` blend mode at
  `var(--vehicle-tint-opacity)`. The `color` mode takes the swatch's hue and
  saturation and keeps the luminance of what is below, which is what preserves
  reflections, shadows and panel seams.

Chromatic colours need both layers: the tint alone over light beige comes out
pink, not red, so the filter darkens the panel first. Neutral colours (white,
black, grey) need only the filter, since a grey has no hue to give.

Each swatch button carries `data-tint`, `data-filter` and
`data-tint-opacity`. `apply(button)` in `home.js` copies them into the three
CSS custom properties on `#heroVehicle` (with neutral defaults for anything
missing) and updates `is-active` / `aria-checked`. Arrow keys move between
swatches like a radio group.

The mask is generated by `tools/build-paint-mask.py`: in this photo the beige
bodywork is the only warm-toned thing, so the script selects warm hue, some
saturation and not-too-dark pixels, with ramps instead of hard thresholds for a
soft edge. **If the hero photo changes, re-run the script and check the
result**; the thresholds are tuned for this beige and this background. It also
writes the WebP copies the page serves.

## `styles.css`

One stylesheet for the whole site (about 7,100 lines). It is organised by
page, and later sections are scoped so they cannot affect earlier ones:

| Lines (approx.) | Section | Scope |
| --- | --- | --- |
| 1–1320 | Base: tokens, menu, wizard shell, progress, steps, step 1 vehicle card, quality cards, 3D view, form fields, confirm button, success | shared |
| 1318–3088 | **Home page**: buttons, header, hero (including the paint layers), services, trade band, process, finish tiers, why us, FAQ, proof photos, contact, footer, WhatsApp button, the hero's one entrance animation | `body.home` and `.home-*` |
| 3089–3663 | **Quote wizard polish**: shell, pinned progress bar, headings, quality cards, camera tabs, parts checklist, fields, footer, success | `body.wizard` |
| 3664–3944 | **Request tracking**: error notice, tracking code, lookup form | shared by the wizard and lookup |
| 3945–4888 | **Matizado sales**: routes, colour card, finder, the six cans, data blocks, summary | `.wizard--paints` |
| 4889–end | **Workshop panel**: login, profile, table, status pills and menus, occupancy pills, parts viewer, monitor, notes, intake, paint table, define dialog | panel classes |

Conventions:

- Colours and easing are CSS custom properties. The logo's ink `#262D40` is
  the main text colour.
- Status colours come from `[data-status="…"]` attribute selectors, so the
  same rule colours the lookup pill, the panel's pills and the monitor badges.
- The panel's status menu is `position: fixed` so it escapes the table's
  horizontal scroll; `src/staff.js` positions it.
- Motion respects `prefers-reduced-motion`.

## Images

| Path | What it is |
| --- | --- |
| `imgs/brand/` | Logo lockups (SVG), favicons, the Open Graph image, and the PNG logos used in emails (`logo-email.png`, `logo-email-white.png`), all traced by `tools/tracelogo.py` from `design/rebrand/logo-source.jpeg`. |
| `imgs/brands/` | Car make logos (SVG), used as a CSS mask in the wizard's step 1 card when there is no photo. |
| `imgs/assets/stock-models/` | One photo per catalogue model, `<make>-<model>.jpg`. Credits and licences in `CREDITS.md` (served, since the licences require attribution). |
| `imgs/assets/suv.*`, `suv-paint-mask.*` | The hero photo and its bodywork mask. |
| `imgs/assets/3d-visuals/<vehicle>/*.glb` | The four 3D models, meshopt-compressed. The uncompressed sources and `.blend` files are gitignored and never served. |
| `imgs/taller/` | Photos of the shop, each in two widths for `srcset`. |

`server/server.js` refuses any path under `imgs/` with a `src` segment, which
is where the raw GLB sources sit on the work machine.
